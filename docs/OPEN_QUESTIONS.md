# Open Questions

这里只保留尚未形成产品决策的问题。已决策内容以 `PRODUCT.md` 和 `ARCHITECTURE.md` 为准。

## 1. Codex 历史与记忆的长期接口

P0 使用官方 App Server 读取用户授权的 task，不直接依赖 Codex 内部数据库或生成的 memory 文件。
仍需观察 Codex 是否提供更稳定的用户记忆授权、编辑和删除接口，再决定是否增加独立记忆层。

## 2. 助理任务的创建与可见性

P0 可以复用现有 thread/start 与固定 task id。仍需真实验收：新建助理 task、App 重启、Codex 升级
和任务归档后，用户是否始终能理解并找回默认助理频道。

## 3. 画像的数据模型

先生成带来源的可编辑文本草稿。只有真实使用证明需要结构化字段、版本或冲突合并时再设计；
在此之前不建设向量库或通用 memory graph。

## 4. 从草稿到自动回复

P0 固定草稿模式。何种联系人、消息类型和授权粒度可以进入自动回复，留待草稿模式的误发、纠正和
撤销数据验证后决定。

## 5. E2EE 发布门槛

当前 Channel Service 可见消息明文。内部验证可以继续使用非敏感内容；面向个人敏感沟通公开发布前，
需决定密钥恢复、多设备、邀请和历史迁移方案，并完成真实威胁模型与验收。
