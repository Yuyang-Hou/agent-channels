# Pijoo Roadmap

路线图按用户价值和验收门槛推进，不承诺日期。

## P0：个人上下文助理

目标：用户拥有可编辑身份的默认助理，并把它安全地分享给多个彼此隔离的联系人。

- 登录后自动建立昵称命名的默认助理频道，并只连接 App 在账号受管目录创建的助理任务；
- App 组合可编辑身份卡与固定安全规则，并在每次投递前复验 task、工作目录与受管权限；
- 通过 Codex App Server 发现、授权、只读检索和撤销历史 task；
- 生成有来源、可纠正、可删除的个人画像草稿；
- 每次分享创建单用途双人 Channel、独立受管 task 和联系人工作区；
- 普通文字自动回复，风险工具继续单独请求批准，并复用现有可靠发送链路；
- 同一服务端托管 Web 共享入口：邀请加入、active Membership 恢复、频道切换和纯文本收发；
- 完成真实账号、Codex task、联系人和撤权验收。

退出条件：`PRODUCT.md` 的十一项 P0 完成标准全部通过。

## P1：日常可用

- 历史授权管理、来源跳转和画像纠正体验；
- 未读摘要、恢复选择、崩溃恢复和可操作错误；
- 联系人资料、AI 印象纠正与跨联系人管理体验；
- 未读计数、跨设备消息历史和 Web 通知；
- Developer ID 签名、公证、升级与卸载闭环；
- 为个人敏感数据的公开使用补齐 E2EE，而不是用 TLS 代替。

## Later：更强的受控自动化

按联系人自定义输出策略、速率限制、紧急停用和跨联系人汇总，等真实使用证明需要后再建设。文件、
Shell、浏览器、网络、部署和付款权限继续单独授权，不随普通文字回复权限继承。

暂不建设第二个 Host、公开目录、独立 Web 后端、Connector 市场、向量数据库或自建模型 Runtime。
